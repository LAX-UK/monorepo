Each of these mutations was caught: removing the dead-letter precedence (5 failures), not counting an in-sync skip as good (3), removing the capability check (8), mapping dry run to not applicable (2), dropping `order_prints_not_mirrored` from the failed reasons (1), dropping `nextRetryAt` (4), and dropping `providerReference` (4). ## Findings

1. **The PR body ends with an AI footer.** The last line of the description is `_Generated by [Claude Code](https://claude.ai/code/session_…)_`, which the brief does not allow. Fix: edit the PR description and delete the `---` rule and the footer line.

2. **A dead-letter can be hidden by a later, unrelated success, so the order shows "Mirrored to Zoho" while its prints are not in Zoho.** See `apps/shop-api/src/application/zoho-mirror/derive-zoho-mirror-state.ts:105` (`if (lastFailing > lastGood)`).
   - Scenario: `shop.order.paid` dead-letters with `print_order_not_mirrored`. Later a `shop.fulfilment.status_changed` event runs with `reportProblems: false`. `apps/worker/src/integrations/zoho/fulfilment/order-mirror.ts:133-142` logs the print problems and still returns `success` once the dispatch record is written (`pass.wrote > 0`).
   - That success counts as "good", so the failure is superseded and the badge says Mirrored. Yet `docs/integrations/zoho.md` and Z2 say this order "already failed for staff". A partial mirror reads as a full one.
   - Fix: make the reader return `domain_events.event_type` with each delivery. For `order`, let a later good delivery supersede a failure only when it is a replay of the same event row, or comes from an event in `ORDER_EVENTS_THAT_SET_PRINTS` (`shop.order.paid`, `shop.print.swapped`), the ones that re-check the prints.
   - Add a unit test and an integration test for "dead-lettered paid, then a dispatch succeeded → failed".

3. **"Mirroring is off" and "not paid" can never show for orders, so staff get the wrong not-applicable copy.**
   - When `ZOHO_FULFILMENT_MIRROR_MODE=off`, the `zoho_fulfilment` projector is disabled (`apps/worker/src/projectors/zoho-fulfilment-projector.ts:19-21`) and queues no delivery rows. `SKIP_REASONS.order.off` is `[]` (`derive-zoho-mirror-state.ts:32`). Every order therefore reads `not_sent_yet`, "Nothing has been sent to Zoho for this yet", instead of Z3's "Zoho mirroring is off".
   - An unpaid order raises no event with a `zoho_fulfilment` delivery: `shop.edition.reserved` has `consumers: []`. So it also reads `not_sent_yet` rather than Z2/Z3's "Only paid orders are sent to Zoho". `order_not_paid` (`:33`) is reached only in a rare race.
   - Z4 takes the mode from configuration (`zoho_sync_health`), not from the newest delivery. The PR body admits the deviation, but the result contradicts Z2's table.
   - Fix, without storing anything:
     - (a) Expose the fulfilment mirror mode as read-only configuration to shop-api, for example the same `ZOHO_FULFILMENT_MIRROR_MODE` env on the shop-api container passed into `ZohoMirrorStatusService`, and return `mirroring_off` / `mode: "off"` when it is `off`.
     - (b) For `order` ids with no deliveries, read the order's paid state through an existing order read port, and return `not_paid` when it is unpaid.
     - Test both.

4. **An artwork whose Zoho status conflicts with LAX shows "nothing to send".** The writeback skip `status_conflict_raised` (`apps/worker/src/integrations/zoho/artwork/zoho-artwork-writeback-service.ts:158-159`) is not listed in `SKIP_REASONS.artwork` (`derive-zoho-mirror-state.ts:35-41`, `failed: []`). It falls to `"other"`, then `not_applicable` / `nothing_to_mirror`, so the copy says "There is nothing to send to Zoho for this" when LAX and Zoho actually disagree and staff were told. This is the artwork twin of `order_prints_not_mirrored`. Fix: add `status_conflict_raised` to `artwork.failed`, and add a unit case.

5. **The order query scans all of `domain_events`, and there is no plan evidence for the claim in the PR.**
   - `drizzle-zoho-mirror-ledger.reader.ts:22,51-52` filters on `payload->>'orderId'`, which has no index. Locally, on a migrated database with 200k `zoho_fulfilment` events, `EXPLAIN ANALYZE` for a 100-id batch planned `Parallel Seq Scan on domain_events` plus `Parallel Seq Scan on domain_event_delivery` (65 ms).
   - `domain_events` holds every event type (bids, users, …) and is never pruned, and the Orders column (PR 3) will run this on every list page load. Z4 asked for the plan to be checked in PR 1. The body says "walks the consumer's own ledger through its unique index", but includes no EXPLAIN output.
   - Fix, with no migration: also constrain `domain_events.event_type IN (<the order trigger types from FULFILMENT_TRIGGER_KINDS>)`. That lets `domain_events_event_type_idx` / `domain_events_event_type_aggregate_id_idx` prune. Paste the `EXPLAIN (ANALYZE, BUFFERS)` output into the PR.
   - If the plan is still a full scan at realistic volume, raise the partial expression index (`((payload->>'orderId')) WHERE event_type IN (…)`) with the owner as its own migration PR before PR 3 adds the list column.

6. **`mode` is hard-coded to `"live"` for failed and mirrored** (`derive-zoho-mirror-state.ts:111` and `:129`).
   - The order mirror fails on print problems before its dry-run check (`order-mirror.ts:121-132` comes before `:139`), so a dead-letter under `dry_run` is reported as `mode: "live"`.
   - The response field is documented as "how the mirror last ran". Fix: return `null` (unknown) for failed and mirrored unless the mode is known (see 3a), and add a test.

7. **The server-side batch limit is not covered by any test.** Deleting `ids.length > ZOHO_MIRROR_BATCH_LIMIT ||` in `apps/shop-api/src/routes/admin/v1/admin-zoho-mirror.routes.ts:31` leaves all 41 tests green, because the schema's `maxLength: ZOHO_MIRROR_BATCH_LIMIT * 37` (`packages/shop-contracts/src/admin-zoho-mirror.ts:47`) rejects the 101-id test first.
   - The length cap also rejects 100 valid ids written as `a, b, …`: 3,798 characters, although `idsOf` trims spaces.
   - Fix: raise `maxLength` to a loose bound such as `BATCH_LIMIT * 40`, keep the count check as the real limit, and add a test of 101 distinct ids whose string fits within `maxLength`, so the 400 comes from `idsOf`.

8. **Copy drifts from Z3 and is incomplete for the UI PRs** (`packages/shop-contracts/src/zoho-mirror-copy.ts:13-16`).
   - Z3 writes "Not mirrored · Zoho mirroring is off." with a `·` separator; the PR uses ". ".
   - The two new reasons, `nothing_to_mirror` and `not_sent_yet`, are not in the approved copy.
   - Fix: use Z3's exact strings and separator. Put the two new lines to the owner, or map them onto Z3's set.
   - Optionally, add the Z3 detail templates for Mirrored, Pending, Failed and Dry run here too, so PRs 2–3 do not write copy inline.

9. **Skip reasons are duplicated as string literals across apps** (low; layering). `SKIP_REASONS` (`derive-zoho-mirror-state.ts:27-42`) and `ZOHO_MIRROR_CONSUMER` copy worker strings (`order-mirror.ts`, `zoho-artwork-writeback-service.ts`, the projector names) with nothing tying them together. A renamed worker reason would silently become "nothing to mirror".
   - The application port also re-declares `MirrorDelivery` (`apps/shop-api/src/application/ports/zoho-mirror.ports.ts:4`), which only structurally matches `ZohoMirrorLedgerDelivery`. That is acceptable, but it is a second copy.
   - Fix: export the reason constants and consumer names from a shared package (for example `@auction/types` next to the consumer catalogue), import them on both sides, and add a contract test that every reason in `SKIP_REASONS` is one the worker can emit.

10. **Informational: artwork state reads only `zoho_artwork_writeback`.** A dead-lettered `zoho_artwork_listing` write (the listing fields) never shows as "Not in Zoho". Z2 says "the relevant consumer", so this is defensible for PR 1. Say so explicitly in `docs/integrations/zoho.md`, or include `zoho_artwork_listing` keyed by the register entry before PR 3.

Not a defect in this PR: the design doc's title on `main` still reads "proposed design, awaiting owner approval". It is worth updating once the owner's approval is recorded.
