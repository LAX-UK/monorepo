## Findings

### 1. Should fix: phone menu has no handling for a failed chunk load
`apps/web/src/components/layout/bid-phone-menu-mount.tsx:27-30`

- **Scenario:** after a deploy (stale tab, old chunk hash gone), offline, or on a flaky phone network, the visitor
  taps "Open menu". `loadPhoneMenu()` rejects. Because of `void …then(...)` this is an unhandled rejection, and
  `menuOpen` is now `true`. The button reads "Close menu" with `aria-expanded="true"`, the header goes solid
  (overlayOpen), and no menu appears. Before this PR the menu shipped with the page, so this could not happen.
  On a data-saver/2g connection there is no idle preload (`connectionIsConstrained`), so every first open
  depends on this fetch.
- **Fix:** add a rejection branch that puts the header back in a consistent state, then retry on the next open.
  For example:
  `loadPhoneMenu().then(c => { if (current) setMenu(() => c) }, () => { if (current && props.open) props.onOpenChange(false) })`.
  A retry already happens naturally because `wanted` stays true. Add a test that mocks the import to reject
  once and asserts `onOpenChange(false)` is called and a later open loads the menu. (The toaster has the same
  no-catch pattern, but a missing toast host is far less harmful than a dead navigation menu.)

### 2. Nit: the window between the first tap and the chunk arriving
Same file. If the menu is opened before the idle preload has finished, the button flips to "Close menu"
straight away and Escape does nothing until the dialog mounts. On a fast connection I could not see it. On a
slow one it could be a few hundred ms. That is acceptable for this PR. If fixing #1, keep the same state
model; don't add a Suspense boundary (the PR's reason for plain state is right).

### 3. Nit: test coverage of the footer composition
`footer-account-links.test.ts` covers the pure link builder, and `marketing-footer.test.tsx` covers the `list`
slot. Nothing renders `SiteFooter` itself to pin that the Account column is the `FooterAccountList` island
(signed-out vs a client vs staff via a mocked `useAppSession`) and that no other column depends on the
session. A small `site-footer.test.tsx` would guard the server/client split against a later edit that
re-introduces `person` into `buildBidFooterColumns`.

### 4. Nit (clean code): `follow-header` tone duplicates the other two
`packages/marketing-ui/src/lax-family-bar.tsx:62-72` hand-writes `on-light` + `group-data…:` + `on-dark`. It is
correct today (verified in the browser). It could be derived (prefix each `on-dark` class with
`group-data-[header-tone=on-dark]/header:`) so the three tones cannot drift. Optional.

### 5. Nit: unneeded double call
`bid-phone-menu-mount.tsx:31-32`: when `open` is true it calls `load()` and also schedules the idle `load`. That
is harmless (the module cache dedupes it), but `if (props.open) { load(); return …cancel only… }` reads more plainly.
