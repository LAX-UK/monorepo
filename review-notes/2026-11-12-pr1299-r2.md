## New notes (non-blocking)

### R1. Low: during a rolling deploy, a new-release write also leaves old instances unable to read tokens

- **Where:** the rollout note in `.env.example` and the header of `packages/db/src/scripts/backfill-xero-token-sealing.ts:9-12`.
- **Scenario:**
  1. Step (3), "confirm no previous-release instance is still running", is placed before `--apply`. But the new release seals and nulls the plaintext on every connect or refresh, from step (2) on.
  2. If an old worker or API instance overlaps a new instance's refresh, the old one reads `null` tokens.
  3. Its refresh then fails, and it marks the connection `needs_reauth`.
- **Impact:** no token is lost, because the old instance cannot write tokens it never obtained, and the sealed copy is intact. The harm is a spurious `needs_reauth` status until the next successful refresh or a reconnect.
- **Fix:** add one line to the rollout note: replace (stop, then start) the api and worker rather than rolling them, or pause the proactive Xero cron until no old instance remains. No code change is needed.

### R2. Info: the main-upgrade test pins the final migration folder

- **Where:** `6bbf9cb6` sets `FINAL_FOLDER_MILLIS = 1806739200000` in `packages/db/src/migration-main-upgrade.integration.test.ts:26`.
- **What:** this is the file's existing convention. Main already pins the latest folder there. So the next migration that merges after this one must bump it again.

## Security and money summary

- **Envelope and key handling:** unchanged from round 1 and still sound. It is AES-256-GCM with a random IV and a dedicated key, and no plaintext is logged.
- **Plaintext at rest:** the new code never writes plaintext. The backfill nulls plaintext with a compare-and-set update.
- **A keyless or misconfigured deploy:** it now refuses to boot (Xero configured) or fails every read before contacting Xero (Xero unconfigured). So a rotated refresh token can no longer be obtained and then thrown away.
- **After merge:** run the backfill `--apply` / `--verify`, force one refresh, and run `VACUUM xero_connection`. This is still recommended from round 1.
