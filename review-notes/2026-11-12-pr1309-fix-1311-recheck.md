Non-blocking notes for the `ZohoTokenStore` adapter in the runtime PR:
- If `version` is `updated_at`, set it with `clock_timestamp()`, or use a bigint counter. `now()` is the transaction start time, so two writes in one transaction, or two writes with equal timestamps, could pass a stale compare-and-set.
- When a compare-and-set fails, a rotated refresh token in that reply is discarded. Today that is fine because Zoho does not rotate, and the planned cross-process lock prevents it later. It is worth a comment or a metric in the adapter.
