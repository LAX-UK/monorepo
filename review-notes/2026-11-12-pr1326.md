# Review: PR #1326, PERF plan PR 5 "sale page islands"

Branch `perf5-sale-page-islands` (head `582d98cb`) compared with `origin/main`. Reviewed on 2026-11-12.

## Verdict: FIX FIRST

The telephone form deferral is sound. A booking or typed input cannot be lost. Ineligible visitors never download the form. The placeholder matches the form's height to the pixel. The hooks are correct. Lenis, the countdown and the socket code are not touched. The sale page really drops 46 KB.

The other two splits (filter sheet and sort select) cause visible changes that the plan does not allow, and they can now fail with no way to recover. The telephone card's failed state also shifts the layout. Each fix is small (see F1 to F3).

## Findings

### F1 (must fix): the filter trigger and sort select now change visibly on client navigation, and a tap on Filters can be lost

Files: `apps/web/src/components/sections/saleroom/saleroom-catalog-filter-sheet.lazy.tsx:17-19`, `saleroom-catalog-sort.lazy.tsx:15-24` and `apps/web/src/hooks/use-deferred-module.ts:23`

- **Visible change on soft navigation.** The old `HydrationDeferred` uses `useSyncExternalStore` and draws the fallback only while the server HTML is hydrating. On a client navigation (sales list → sale, or Back from a lot page, the most common path) it drew the real control at once. `useDeferredModule` always starts `idle`, so every mount draws the fallback first, even when the chunk is already cached. I confirmed this with a temporary test: mount, wait for ready, unmount, mount again. On the first commit of the second mount there is no `combobox "Sort lots"` and no "1 active filters" badge. With `?status=live`, the badge blinks off and on. The sort control also changes width from the plain-text span to the select (`min-w-[9.5rem]`), which moves the toolbar row. The plan does not approve this.
- **Lost tap and dead state.** The fallback `<MarketingFilterTrigger activeCount={0} />` is a real `<button>` with no handler. Before, it was inert only until hydration. Now it stays inert until the filter chunk arrives (vaul and the sheet), which takes seconds on a slow phone. A tap in that window does nothing. If the import fails or takes more than 10 s, the status stays `failed` and nothing ever retries. The phone filters stay a dead button and sorting stays plain text **for the rest of the visit**. This could not happen before because the code was in the page's own chunk.
- **Fix:**
  1. Have `useDeferredModule` remember resolved modules at module level, for example a `WeakMap<load, value>`, and start in `ready` when the module is already cached. Otherwise keep `HydrationDeferred` around the lazy parts so that soft navigations behave as before.
  2. Have the fallback trigger record the tap: `onClick={() => { wantOpen.current = true; if (failed) retry(); }}`. When the sheet arrives, mount it open, which needs an `open`/`defaultOpen` prop. On `failed`, retry when the control is next pressed, pointed at or focused.
  3. Draw the fallback badge from `useSearchParams()` with the existing `countActiveSaleroomStatusFilters`, which is cheap and already in the page. The badge is then correct from the first paint.
  4. Add a test: a click on the trigger while the chunk is pending opens the sheet once it arrives.

### F2 (must fix): the telephone card's failed state shrinks the card, which shifts the layout

File: `apps/web/src/components/marketing/sale-telephone-booking-panel.lazy.tsx:60-68`

The placeholder is 338 px (desktop) or 362 px (touch). The failed block (one line of text and a button) is about 100 px. On a slow network the card collapses by about 240 px after 10 s, moving everything below it. When the late chunk arrives (the hook flips `failed` to `ready`), the card grows back. That is two shifts nobody asked for. The approval was for "deferral without layout shift". **Fix:** give the failed state the same box as the placeholder, for example by wrapping both in a container with the placeholder's height or `min-h`, or by laying the message and button over the placeholder bars.

### F3 (should fix): failed-state accessibility and focus

File: `apps/web/src/components/marketing/sale-telephone-booking-panel.lazy.tsx:54-68`

- The failure text is not announced. Add `role="alert"`, or `role="status"` with `aria-live="polite"`, on the failed block.
- Pressing **Try again** unmounts the button (`failed` → `loading` → placeholder), so focus drops to `<body>`. A keyboard or screen-reader user then starts again from the top of the page. Keep focus in the card: make the wrapper `tabIndex={-1}` and focus it on retry, or keep the button mounted with `aria-disabled` while it retries.
- Placeholder: the bars use `Skeleton`, which is `aria-hidden`. The note is real text and `aria-busy` is set on the wrapper. That part is fine.

### F4 (should fix): a test that cannot fail

File: `apps/web/src/components/sections/saleroom/day-gallery/saleroom-day-gallery.test.tsx` ("starts fetching the sheet when View all is pointed at")

`expect(preloaded.sheet).toBeGreaterThanOrEqual(before)` is always true. Also, the `vi.mock` factory runs once per file, so an earlier test has usually already loaded the module and the counter cannot move. Spy on the preload instead (mock `day-gallery-view-all-sheet.lazy` and assert that `preloadDayGalleryViewAllSheet` was called on `pointerEnter` and `focus`).

### F5 (nice to have): missing tests for the main promise

There is no `sale-telephone-booking-card` test proving that signed-out, KYC-pending, unverified-mobile, no-buyer-profile and existing-booking states **never** call the loader. Reading `TelephoneParticipationGate`, I confirmed they don't: it returns early and never mounts `children`, and dynamic `import()` chunks are not prefetched. Still, a regression test should hold that, for example by mocking `use-deferred-module` or the panel module and asserting it is never imported or rendered. The lazy-form failure test only shows that the failure repeats. A "fails, Try again, form appears" case at component level would cover the retry path the brief cares about.

### F6 (low): next/dynamic failure for the day gallery sheet

File: `apps/web/src/components/sections/saleroom/day-gallery/day-gallery-view-all-sheet.lazy.tsx:16`

`dynamic(..., { ssr: false })` without an error boundary throws a failed chunk load to the route's error boundary. Pressing "View all" offline would replace the sale page with its error screen. This copies the existing `LazyMediaLightbox` pattern, so it is not new risk in kind. Consider a small error boundary around both lazy overlays, or `useDeferredModule`. There is also no pressed or busy feedback while the sheet is fetched on a cold tap. The tap is not lost: `sheetMounted`/`sheetOpen` are set at once and the sheet opens when it arrives. vaul 1.1.2 animates with CSS keyframes on `data-state=open`, so mounting already open still slides in. Focus returns to the pressed control because it is `document.activeElement` when the sheet opens.

## Points checked and found correct

- **Input and bookings cannot be lost.** The form only appears when status is `ready`. Neither `enabled` (`near || jumping`, both latched true) nor `load` (module-level) can change afterwards, and `retry` is only reachable from `failed`. So the hook can never leave `ready`, and the form is never remounted while someone types. A late arrival after the timeout moves `failed` to `ready`, and nothing could be typed before that. Double load (Strict Mode, or a retry during an in-flight import): the previous run is `cancelled` and `import()` is cached, so the same component reference arrives. Double submit is still blocked by `pending` (unchanged). On success the card owns `done` and `createdBookingId`, the same states as before but lifted out of the form. Network failure on submit: `rootError` path unchanged. After a rejected chunk load, webpack 5 clears `installedChunks`, so **Try again** really fetches again.
- **Who downloads the form.** It mounts only as the gate's `children`. Signed out, not verified (KYC or mobile), no profile, and an active booking all return early. A cancelled booking can book again and does get the form, as before.
- **The placeholder height matches exactly.** I rendered both with the app's compiled CSS in Chromium:

  | Viewport | Real form | Placeholder | Rows (fields, note, button) |
  | --- | --- | --- | --- |
  | Desktop 1280 | 338 px | 338 px | 60/60/102/16/36 = same |
  | iPhone 13, Pixel 7 (coarse pointer, `lax-target`) | 362 px | 362 px | 60/60/102/32/44 = same |

  Both are the same with and without `data-lax-density="client"`. A server-side `rootError` cannot exist before the form is present.
- **Hooks.**
  - `useNearViewport` disconnects on cleanup and once near. It does nothing during SSR (effect only). Without `IntersectionObserver`, or without the element, it answers true at once.
  - `useAnchorIntent` removes its listeners and stops listening once triggered. It reads the hash on mount. Its selector matches the sub-nav's `href="#telephone"` (`marketing-sub-nav-anchor.tsx:285`). `pointerover`/`focusin` on the tab come before the Lenis `scrollTo` click.
  - `useDeferredModule` clears the timer on resolve, reject and cleanup, and does no `setState` after unmount.
  - Small note: `{ passive: true }` is passed to `addEventListener` but not to `removeEventListener`. That is harmless because only `capture` has to match.
- **Lenis.** No Lenis file changed. The `SmoothScroll` module (`lerp:.1`) is byte-identical in both builds.
- **Live countdown and socket updates.** `saleroom-detail-view.tsx`, the live providers, the banner and the socket client are not in the diff.
- **What left the sale page's start-up set.** I confirmed it in the built chunks: react-hook-form, the Radix `Select` set (`SelectScrollDownButton`), cmdk (13.8 KB raw) and the zod form schema are gone. vaul was not in the start-up set before either.

## Ratchet re-records (home, sales list, lot, plus about and terms)

I built main and the PR with CI's environment and compared the modules in each route's start-up files:

- **Home, sales list, about:** the module **set and sizes are identical**. Every added module id matches a removed one of the same raw length; ids changed only because server-action hashes changed. The growth comes from webpack regrouping:
  - Home now loads **46 files instead of 45**. A new chunk `97003` (7.7 KB gz) shared by home and the sale page took modules out of home's page chunk, for example a 12.4 KB-raw card-rail module, the image fallback and the sales API helpers.
  - `76177` (the Lenis/Reveal chunk) gained the `cn` helper (+277 B gz), which moved there from elsewhere.

  One extra request and a lower compression ratio give about +1.05 KB gz on home and +1.08 KB on sales list.
- **Lot:** 56 files instead of 55, with raw modules about 1 KB smaller overall. Net +0.86 KB gz, again from chunk boundaries.
- **Frame +0.2 KB on every route:** the webpack runtime chunk map grew to name the four new async chunks. This is expected and cannot be avoided.

**Judgement:** the re-records are justified. No route gained code, and only the sale page's code changed. A follow-up could probably recover about 1 KB on home and sales list by keeping the 97003 group together, for example a `splitChunks` cache group or `minSize` for marketing page chunks shared by 2 routes. That is a global bundler change with its own risk, so do it as its own small PR measured on all routes, not here. The new sale budget of 593 KB leaves about 54 KB of headroom over 538.7. That is in line with the margins on the other groups.

## Summary of required changes before merge

1. F1: no fallback flash when the chunk is cached (soft navigation). The filter tap must open the sheet once it arrives, and the filter and sort must recover after a failure. Draw the fallback badge from the search params.
2. F2: the failed state keeps the placeholder's height.
3. F3: announce the failure and keep focus in the card on retry.
4. F4: replace the always-true test assertion.

F5 to F7 can follow in this PR or the next one.
