## Findings

No blocking findings.

1. (Low, accepted trade-off) `apps/web/src/lib/auth/services/send-verification-email.lazy.ts:13`:
   the first press of a "send / resend verification email" button now waits for one extra chunk before
   the request starts. Scenario: unverified bidder on the lot page on a slow connection presses
   "Resend email"; the button stays in its busy state a little longer before the success toast. The
   visible states are the same as before. Not a menu/dialog/cookie-dock/toast interaction. Optional fix
   (not required): warm the import on pointerenter/focus of the button.
2. (Info, unreachable) `apps/web/src/lib/workspace/account-needs-you.client.ts:17`: `isIndexableObject`
   accepts a `Map`/`Set`/`Date`/thenable where Zod 3 would reject it. The input is always `res.json()`
   output, which can never be one of those, so results are identical in practice. No fix needed.
3. (Info) `packages/validators/src/marketing-attribution.ts:183`: the hand regex mirrors Zod 3.25's
   date-time pattern. If `zod` is ever upgraded (the range is `^3.24.1`), the cookie parser and the API
   schema could drift; `marketing-attribution-parse.test.ts` runs both side by side, so the drift would
   fail CI. No fix needed.
