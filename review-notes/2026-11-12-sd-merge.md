## Conflicted files and how they were resolved

### apps/auth/src/services/account-identity.service.ts (6beca670)
- `:125` `isCurrent: session.id === current.id`. `current` comes from `RecentSessionGuard.findLive`. That lookup searches only the subject's own live sessions, first by exact id and then by `previousIds`. A takeover-renamed sid therefore marks the row that replaced it, and a sid that belongs to someone else matches nothing, so the call returns `reauth_required`. The test "does not resolve another person's earlier id" covers this.
- `:126` `signedInWith: signedInWithOf(session.amr)` is main's change, kept intact. It applies per row and exposes only the method label, not the raw amr or the IP address.

### apps/auth/src/services/account-sign-in-methods.service.ts (6beca670)
- `removePasskey` `:190-209` and `unlink` `:227-256` call `operations.removePasskey(subjectId, passkeyId, current.id, this.passkeysOffered())` and `unlinkSocialSignIn(subjectId, provider, current.id, this.passkeysOffered())`. The argument order matches the service signatures (`identity-operations.service.ts` `keepSessionId` 3rd, `passkeysOffered` 4th). Main's `passkeysOffered` is preserved in both calls.
- **Step-up is still enforced.** `current` comes from `findRecent` (`recent-session-guard.ts:46`), not `findLive`. `findRecent` accepts only the exact live session id inside the step-up window. A takeover or earlier id never inherits the recency of the row that replaced it, so a stale or taken-over sid gets `reauth_required`.
- **No cross-session or cross-person effect.** `current.id` is always the caller's own live row id, scoped to `subjectId`. The passkey delete and social unlink are scoped to `subjectId` in the transaction. `deleteOtherSessions` and the durable `revoke_tokens_except_session` keep only `current.id` and are also scoped to `subjectId`. A stale id cannot pick which session survives, because it is refused before any write.
- The last-method rule works as on main: when passkeys are not offered, held passkeys do not count as a way in.

### apps/auth/src/services/identity-operations.ports.ts (6beca670, 37c89007)
- `IdentitySessionRecord` has both sd1's `previousIds: readonly string[]` (`:47`) and main's optional `amr?` (`:49`). sd3 also adds `lastActiveAt`, `signedInAt` and `isStaff`. Nothing was dropped.

### apps/auth/src/infrastructure/drizzle-identity-session-repository.ts (37c89007)
