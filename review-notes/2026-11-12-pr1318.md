- Branch: `bs1-reoffer-admin` @ `23972df5`, compared with `origin/main` @ `d8063ba0`
- Date: 2026-11-12
- Scope: money, security, design. Independent review. The PR branch was not changed.

## Verdict: FIX FIRST

There is one correctness bug that has to be fixed before merge. Sales staff's inbox would
collect high-severity re-offer items that can never clear, because the reader doesn't notice when
a lot has gone back to inventory. The integration test that claims to cover this case sets the
wrong columns, so it passes anyway. Everything else is either low severity or a follow-up.

The money and security points all hold:
- The price is the highest placed bid, never a hidden maximum.
- The new GET routes are limited to lot readers.
- Every mutating route checks permission and step-up on the server.
- The shortfall is visible to staff only.

## Findings

### 1. FIX FIRST: re-offer inbox items never clear after "Return to inventory"

- **Where:** `packages/persistence/src/repositories/drizzle-reoffer-work-items.reader.ts:113-129`.
  The test that misses it is `packages/persistence/src/repositories/drizzle-reoffer-staff.integration.test.ts:265-275`.
- **What happens:** for a closed offer (`declined`, `expired`, `seller_declined`, `seller_lapsed`),
  the reader keeps an item while `lot.winner_id IS NULL` and the offer is the lot's latest.
  Returning a lot to inventory (`resetLotForInventoryReturn`,
  `drizzle-lot-transition.repository.ts:13-31`) sets `status = 'draft'` and `winner_id = NULL`,
  and it leaves the re-offer rows alone. So the condition stays true after the lot has left the
  re-offer flow.
- **Scenario:** an offer is declined, and staff use the card's "Return to inventory…". The lot is
  now a draft, but the inbox keeps showing "Re-offer: declined or ended". It is high severity with
  a 48h SLA, so it goes overdue and never clears. A lapsed seller request does the same thing as a
  `reoffer_no_reply` item.
- **Reproduced:** the probe on the real DB set the lot to `status draft, winner_id null`, as the
  real return does. The reader then returned `["reoffer_no_reply","reoffer_decision"]`.
- **Why the test passes:** the "lot back in inventory" case sets `winnerId: buyerId`. A real
  return-to-inventory clears the winner rather than setting one, so the test only covers a
  re-award.
- **Fix:**
  - Require `eq(lot.status, "ended")` in the branch for closed offers. This matches
    `showsReofferCard` in `apps/web/src/lib/admin/reoffer/reoffer-lot-state.ts`, which already
    uses `status === "ended" && !hasWinner`.
  - Consider the same check for `awaiting_seller` and `ready`, unless return-to-inventory is
    already refused while an offer is open. I didn't verify that; please confirm.
  - Change the test to set `{ status: "draft", winnerId: null, saleId: null, lotNumber: null }`,
    and keep a separate case for a re-awarded winner.

### 2. Copy is wrong: the read-only note names Finance, which can't open this page

- **Where:** `apps/web/src/lib/admin/reoffer/reoffer-card.vm.ts:17-18`. The note says "Only Sales
  managers, Finance and Administrators can act on a re-offer."
- **Why it's wrong:** someone who holds only the Finance role can't enter platform admin routes
  (`canAccessPlatformAdminRoutes` in `packages/types/src/role-policy/role-route-policy.ts:17-23`),
  so Finance never sees the lot page or this card. Also, recording the seller's answer is
  `auction.manage` only.
- **Fix:** say "Only Sales managers and Administrators can act on a re-offer." Or, if Finance
  should act on re-offers, add a route for them. The RA intent reads as sales-only from the lot
  page.

### 3. Low: the notice tells staff the seller will be asked again, even for LAX-owned stock

- **Where:** `apps/web/src/lib/admin/reoffer/reoffer-card.vm.ts:318`. The text is "…The seller will
  be asked again[, because the price is lower]."
- **Why it's wrong:** `consentRequirement` (`packages/domain/src/reoffer-consent.ts:37-51`) never
  asks for LAX-owned lots, and it asks for every other lot whatever the price. So the sentence is
  wrong for LAX-owned stock, and "because the price is lower" suggests a rule the domain doesn't
  have.
- **Fix:** base the text on `offer.consentStatus === "not_needed"` ("No seller consent needed:
  LAX-owned"). Otherwise say "The seller will be asked again." and drop the price clause, or keep
  it only as a fact ("Their bid is lower than the last offer").

### 4. Low: the Buyer default dialog can show the wrong lot's next bidder, and a step-up during the follow-on start isn't handled

- **Where:** `apps/web/src/components/admin/lots/use-buyer-default-dialog.tsx`:
  - line 205: the preview promise has no guard against a newer `open()`.
  - line 262: when the start fails, it only calls `notify.error`.
- **Scenarios:**
  - (a) Staff open the dialog for lot A, close it, then open it for lot B before A's preview
    returns. A's next bidder then appears under B's "Offer to the next bidder" option. Staff
    could record a default on B thinking they're offering to A's bidder. The server still picks
    the right bidder, so this misleads but doesn't charge anyone.
  - (b) The default succeeds but `adminStartReofferResultAction` comes back with a step-up code.
    Staff get a generic error and no re-auth prompt.
- **Consistency:** this is fine. The default is committed on its own, and the lot page then shows
  the Re-offer card with "Offer to the next bidder…" (`showsReofferCard`: default present, no
  offers, status `ended`, no winner). That matches the comment "if the offer cannot start, the lot
  page offers it again".
- **Fix:**
  - (a) Keep a ref to the current target id and drop results for any other lot.
  - (b) Pass `started` through `stepUp.handle(started, "start this offer")` before falling back
    to the error toast.

### 5. Low: kit rules for StepList and the Section status slot

- **Where:** `packages/staff-ui/src/display/step-list.tsx`.
  - Line 61: `key={line}` gives a duplicate React key when two detail lines are the same.
    Use the index or `${item.id}-${i}`.
  - Line 52: `mt-[5px]` is an arbitrary value. Every other part of the kit uses tokens. Use a
    spacing token (e.g. `mt-1`) or line-height alignment.
- **README:** `packages/staff-ui/README.md` asks that the component list and the design-standard
  **Kit** lines be updated in the same PR. Neither `StepList` nor `Section`'s new `status` prop is
  listed.
- **Section:** the `status` slot only adds a flex wrapper around the `h2`. It doesn't restyle the
  `h2`, so existing sections look the same. Good.

### 6. Info / follow-up (not blocking)

- **"How they told us":** the dialog joins the channel and the note on the client
  (`record-seller-answer-dialog.tsx:55`, `"Phone: …"`).
  - The server enforces the shared `note` schema: trimmed, 1 to 1,000 characters. The dialog caps
    the free text at 900, so the result always fits.
  - The note is shown only as React text. There is no `dangerouslySetInnerHTML`, and it is only
    ever stored as a bound column, so there's no injection path.
  - The weakness is that a crafted request can store any prefix. If the channel matters for audit,
    add a `channel` enum to `recordSellerAnswerBodySchema` and store it as a column.
- **Load on every lot page:** `getLotReofferBundle` runs on every lot page
  (`layout.tsx:58`, the Overview and the Bids tab, shared through `cache`). That adds three API
  calls per page view, including `reoffer-preview`, which reads all bids and loops
  `selectNextBidder`. Consider skipping the preview and offers when `buyer-default` returns `null`
  and the lot isn't `ended` with a winner.
- **Fallback date:** `reoffer-preview.service.ts:80` falls back to `new Date()` for `placedAt`.
  The bid always exists, so this can't happen today, but if it ever did, staff would see "now" as
  the bid time. Throwing would be better.
- **Stale end-date labels:** `send-offer-dialog.tsx:57` works out the end-date labels once, when
  the dialog mounts (`useMemo([])`). If the dialog stays open across 17:00 London, the labels are
  out of date. The server works the date out again, so this is cosmetic only.

## Checks that passed

- **Hidden max bids:** `placedBids` reads only `bid.amount` (`drizzle-reoffer-workflow.reader.ts:156-158`).
  No new reader, view model or Bidding-tab tag reads `max_auto_bid_amount`. The preview price is
  the bidder's placed bid.
- **New GET routes:** `reoffer-preview` and `buyer-default` sit behind `requireLotsRead`
  (catalogue.write, auction.manage, platform.admin.full or admin.read). This matches the lot page
  layout gate (`LOTS_READ_ACCESS`). Route tests cover:
  - 200 for administrator, sales_manager, cataloguer and read_only
  - 403 for saleroom_clerk, client_services, fulfilment, compliance and clients
  - 401 for anonymous users
- **No new data for these roles:** lot readers already see bidders on the Bids tab. The
  shortfall, seller proceeds and the voided invoice are now visible to cataloguer and read_only.
  The RA says "staff only", and this fits that. Flag it to the product owner if "staff" was meant
  to mean sales only.
- **Mutating routes:** these are unchanged and all have permission plus `requireStepUp` on the
  server. Start, send and withdraw use `requireBuyerDefault`. Seller answer uses
  `requireAuctionManage` and needs a note. The existing route tests cover each role and the
  step-up. The web server actions also check the same capability first.
- **Inbox access:**
  - All four kinds use `SALES_ACCESS`, and the test shows finance, cataloguer, client_services
    and read_only don't see them.
  - Finance-only staff can't reach `/admin` platform routes (`canAccessPlatformAdminRoutes`), so
    sending these items to sales is right.
  - The links go to `/admin/lots/:id`, and the staff-alert link contract test was extended.
- **Rules:** the 1–7 day window ending at 17:00 London comes from the shared domain `offerEndsAt`.
  Server dates use `@auction/datetime` (`formatDayMonthOnly`, `LONDON_TIME_ZONE`). The cap of 3 is
  `MAX_REOFFERS_PER_DEFAULT`. ATG-sold lots return `soldOnAtg` with no next bidder, and the lot
  menu disables Buyer default and links to the runbook.
- **Design:** the card's view model is pure and the component only draws it, which keeps the
  design clean (SRP). The `ReofferPreviewService` is narrow and has ports injected. The
  `priceOf` refactor reuses the invoice's own pricing, so staff see the same total the bidder will
  be charged.
