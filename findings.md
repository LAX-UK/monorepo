# Zoho / accounting systems audit (independent, 2026-11-19)

Scope: origin/main at `33ca431d` (PR #1561 is merged, so it is audited as part of main). The audit covers how LAX Bid, lax.art, LAX Shop, LAX Account/auth and the worker sync with:

- Zoho CRM: Contacts/Leads, Deals, Products (the artwork master), Print_SKUs, Print_Products, Edition_Ledgers, Framing_Jobs and Dispatch_Fulfilments
- Zoho Inventory
- Zoho Books
- Xero

Each code path was traced from publisher to consumer to mode switch to ledger/dead-letter to staff read, and checked against `docs/integrations/zoho.md`, `docs/design/*` and the package READMEs. Earlier reviews were not relied on.

No P0 found: no confirmed money loss or data loss. The VAT allocation in #1566 was fuzzed (~100k invoices, mixed old/new rules, splits, named-line credits) with zero over-credit, zero leftover and exact rebuilds.

## Verified working as documented (end to end)

- **#1559**: the Redis budget, rate window and refresh lock are atomic and fail closed (integration test ran against real Redis). Not wired at runtime yet; see F17.
- **#1560**: private-deal invoicing is refused everywhere. There is no bypass through checkout, bank transfer, settlement or payout, and no outbound consumer. See F20.
- **#1562/#1568**: `terraform-test-up.yml`, `terraform-apply-test.yml` and `terraform-apply-test-dispatch.yml` all pass the fulfilment mirror mode and location mode, defaulting to `dry_run`. Plan and drift-check do not; see F5.
- **#1563**: the catch-up touches only that consumer's `dry_run` skips for its own event types. It refuses unless the mode is `live`, pages by 500, is bounded by the starting count and is idempotent. Requeued rows sort ahead of newer events. The skip reason `dry_run` is the same string in the writeback, listing, order mirror and print-group mirror.
- **#1564**: the location consumer has its own cursor and ledger, and reads the current location via the store LAX Admin uses. It writes only on a difference, under the listing's advisory lock. The nightly check runs at 03:30 and its repeatable is removed when the mode is off. `live` is in `writesToZohoCrm` (org guard), the OAuth trio is required when not off, and dead letters are labelled "Zoho artworks (stock location)".
- **#1565**: the post-write check is sound. LAX's own write moves `Modified_Time`, but a conflict needs a different, non-replaceable Status as well, so LAX's write alone never raises one. A stale read with an unmoved `Modified_Time` logs as unverified. The integration-user lookup is cached with a 15-minute failure back-off, and Status writes are serialised with the listing and location by the shared lock. Residual race as documented; see F12.
- **#1566**: no over-credit or leftover; mixed old/new notes reconcile; the marker persists; release rebuilds use the stored rule; Xero credit notes (`xero-payment-recorder.ts:130-187`, one NoTax line) are untouched.
- **#1567**: the refund finds the deal by `shop-order:<orderId>`, the same key as paid. A failed refund skips; a held deal skips (documented gap). Routing is as documented: `shop.refund.reversed` goes to `accounting` only. Notes are erased with the person's links. See F2, F3, F13, F23.
- **#1561**: `canary` is identical to `live` everywhere: delivery mode, release sweep, org check, backfill. The badge SQL, the ordering, the per-part repair and the 100-id batch are correct. See F1, F15, F16.

## Systems map corrections

The summary below was checked statement by statement.

> Zoho CRM Products = artwork master; Inventory unused; Books dry run only, Xero live for Bid; private deals have no invoice issuer; CRM sync canary with 4 events; write-backs listing dry_run, status off, fulfilment mirror and stock location default dry_run on test once infra #71/#72 merge.

1. **"Zoho CRM Products = artwork master"** holds only for the catalogue fields: title, artist, medium, dimensions, year and Status for a gallery sale. LAX is master for:
   - the stock code (and overwrites Zoho's copy, F4)
   - where an artwork is offered, and therefore the Status LAX writes under compare-and-set
   - `LAX_Listing*` and `LAX_Location`
   - prints: Print_Products, Edition_Ledgers and Print_SKUs are created and overwritten by LAX from LAX Shop listings; nothing reads them back; master is an open owner decision (zoho.md:333).

   "Products = artwork master" must not be read as "Zoho is master for print SKUs".
2. **"Inventory unused"**: correct. Nothing in the code calls Zoho Inventory. The only "inventory" in the code is LAX Shop's internal inventory API (`SHOP_API_INVENTORY_BASE_URL`, the inventory machine credential).
3. **"Books dry run only"**: correct. Only `createZohoBooksDryRunAdapter` is built, `BOOKS_ORGANISATIONS` is empty, and the HTTP client and #1559's shared limits are not wired.

   **"Xero live for Bid"** is environment-dependent, not a code fact. Legacy Xero writes (invoices, payments, payout bills, refund credit notes) run whenever `XERO_CLIENT_ID` is set and a connection exists. The `xero` projector is a separate path, gated by `XERO_PROJECTOR_MODE` (default `off`, not passed by any workflow).
4. **"private deals have no invoice issuer"**: correct in every environment as of #1560. Add: they also reach no accounting system or CRM, because every `private_sale_deal.*` event has no consumer.
5. **"CRM sync canary with 4 events"**: wrong as stated.
   - `canary` is not a distinct mode; it equals `live`.
   - The test default is `ZOHO_CRM_SYNC_MODE=dry_run` with allowlist `user.registered` (one event).
   - Four lifecycle types (`user.deletion_requested`, `user.deletion_cancelled`, `user.identity_merged`, `user.identity_deleted`) come on automatically with any person type, and `shop.guest_lead.erased` with guest leads or enquiries.
   - The "4 events" appear only in the runbook's rollout phases (`zoho-crm-test-rollout-phases.md`, phase 2 or phase 3), and the new Shop refund and fulfilment types are in no phase.

   23 event types route to `zoho`. The live state is whatever the GitHub `test` vars say, which this audit cannot read.
6. **"write-backs: listing dry_run, status off, fulfilment mirror and stock location default dry_run on test once infra #71/#72 merge"** is broadly right for the up/apply workflow defaults: listing `dry_run`, writeback (Status and stock code) `off`, fulfilment `dry_run`, location `dry_run`. Corrections:
   - (a) The listing and fulfilment `dry_run` defaults already apply today; only location (and fulfilment, if #71/#72 add its variable) wait on infra.
   - (b) With the writeback `off`, the nightly Status pass is off too.
   - (c) The listing's `dry_run` makes unchanged artworks read "Mirrored, live" on the badge (F1).
   - (d) Plan and drift-check will disagree with these defaults (F5).
   - (e) The fulfilment `dry_run` fails every paid order's reads until the owners add `LAX_Order_Ref` and the related fields in the sandbox (documented).

   Unverifiable here: the infra repo's variable declarations and defaults, and whether #71/#72 are merged.
